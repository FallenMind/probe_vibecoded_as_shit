# Игровой каркас

Действующая игра запускается через `src/main.ts` и использует `runtime/game.ts`, `StateBus` и `GameState`. Карты, персонажи, оружие, алхимия, улучшения, испытания, анимации и сохранение собраны в `src/game/`.

Прежняя реализация удалена. Это единственный активный игровой код и единственный источник состояния. Формат нового сохранения отдельный; конвертера старых сохранений нет.

## Устройство

Для работы с картами и клетками используется `world/mapAccess.ts`; независимые клипы и проигрыватели находятся в `animation/animation.ts`. `animation/gameVisuals.ts` запускает их от игровых событий, а `animation/canvasVisuals.ts` отображает на Canvas. Подробности и ограничения — в мини-вики.

```text
                       команды / события
интерфейс ───────────────┬─────────────────────┐
                         ▼                     ▼
                  StateBus: ресурсы,       GameplayMode
                  персонажи, карты,        (правила забега)
                  уровни, данные модулей        │
                         │               генерация / бой /
             ┌───────────┼───────────┐   награды / испытания
             ▼           ▼           ▼
        движение      оружие      алхимия ─ улучшения
                         │
                планы атак и движения
```

* `core/model.ts` — данные персонажей, карт, клеток, ресурсов и уровней улучшений. Идентификаторы строковые: новый ресурс или персонаж не требует менять общий перечень типов.
* `core/contracts.ts` и `core/gameplay.ts` — контракты модулей, режима игры, движения, оружия, генерации карты, обработки атак, наград, испытаний и артефактов. `GameplayController` делегирует правила переданному `RunRules`; таким образом можно позже заменить pre-infinity другим режимом.
* `core/stateBus.ts` — общий доступ к состоянию, атомарный обмен ресурсов, события и вызовы модулей. Модули регистрируются, заменяются и отключаются по id. Таймеры рецептов и оружия хранятся в состоянии, а не в глобальных переменных.
* `weapons/` — общий `Weapon`, базовая обработка интервалов и отдельный файл на кулаки, кирку, копьё, игломёт, излучатель и бомбарду. Ближнее оружие запрашивает движение; автономное использует тот же контракт и движения не запрашивает. Игломёт выбирает заднюю цель, излучатель ищет плотное скопление около задней части карты. Каждый план включает обязательный `direct` с точной клеткой и список `splash`: основная цель в каждом из них исключена из повторного попадания. Сквозной урон снаряда тоже описывается как `splash`.
* `alchemy/` — независимые рецепты Земли, Воды, Воздуха и Огня, ручные обмены и контракт усилений. Количество сырья, результаты, лимиты, режим процента от запаса и интервалы задаются данными рецепта.
* `upgrades/` — повторяемое и одноразовое улучшение с ценой, условиями, переключателем и описанием эффектов. Цикловые улучшения используют те же классы, что и обычные. `resolveStat` вычисляет эффекты из уровней без изменения базовой настройки.
* `config/` — типизированные параметры мира, оружия, алхимии, персонажей, прогрессии, ввода, испытаний, эффектов и сохранений. Параметры, ещё не подключённые к исполнителям, перечислены ниже.

## Как обращаться к каркасу

```ts
import { createDraftFramework, addCharacter } from './index';

const { bus, config } = createDraftFramework();
bus.exchange({}, { stone: 1000 }); // Выдать ресурс через общую шину.
bus.invoke('alchemy.earth', { type: 'set-enabled', payload: true });
bus.tick(1);
const snapshot = bus.snapshot(); // Изолированная копия для интерфейса или сохранения.

addCharacter(bus, {
  id: 'companion', mapId: 'start', position: { x: 5, y: 5 },
  movementSpeed: 2.5, attackSpeed: 1, enabled: true,
  controlledWeapon: null, autonomousWeapons: [], weaponStates: {}, tags: [],
}, config.characters.maxCount);
bus.invoke('weapons', { type: 'equip', payload: { characterId: 'companion', weaponId: 'spear' } });
bus.setEnabled('alchemy.water', false);
// После покупки улучшение можно выключить и вернуть без повторной оплаты:
bus.invoke('upgrades', { type: 'set-enabled', payload: { id: 'fists.damage', enabled: false } });
```

`bus.read()` отдаёт типизированное представление состояния без копирования; изменять его следует через `update` и `exchange`. `snapshot()` делает полную копию. `exchange` сначала проверяет все входы и ограничения вместимости и затем проводит обмен целиком. `listModules` показывает зарегистрированные модули и их состояние, `invoke` адресует команду конкретному модулю, а `subscribe` позволяет слушать события. `setPaused` останавливает тики и команды; прямые административные вызовы `update` и `exchange` по-прежнему доступны. Модуль можно заменить через `replace`; его данные в `moduleData` при этом сохраняются.

У каждого персонажа отдельные позиция, скорость, выбранное оружие и таймеры. Список автономного оружия не ограничен одним типом, а `primaryCharacterId` обозначает основного персонажа. В сборке создаётся только `main`.

## Улучшения и порядок баффов

Для одного расчёта собираются активные эффекты по всем подходящим ключам, например `weapon.damage`, `weapon.melee.damage` и `weapon.fists.damage`. Они проходят один общий пайплайн:

```text
((база + сумма baseFlat) × произведение mult + сумма exitFlat) × произведение outputMult
```

Плоские значения умножаются на уровень. Для множителей `value: 1.1` означает ×1,1: `stacking: 'linear'` на двух уровнях даёт ×1,2, `compound` — ×1,21. По умолчанию используется `compound`. Округление и ограничения принадлежат механике, которая запросила характеристику. Пример повторяемого улучшения силы кулаков стоит в `baseFlat`, а множитель урона цикла — в `outputMult`. Пайплайн уже используется для урона, скорости атаки и радиуса сплеша в планах оружия.

Уровень и включение хранятся отдельно: выключение не возвращает стоимость и не удаляет покупку; покупка следующего уровня сохраняет выключенное состояние. Требования к другим улучшениям пока проверяют факт покупки, независимо от переключателя. Запросы параметров и механик учитывают только включённые улучшения.

Главное назначение временного отключения — испытания. Оно хранится отдельно от выбора игрока: `upgradeSuppressions` содержит независимые ограничения по источникам. Каждое может отключать все улучшения, указанные id или улучшения с заданными тегами. Совпадение по любому из условий подавляет и числовые, и особые эффекты, включая эффекты покупок, сделанных во время испытания. Уровни и цены при этом не меняются. Пока действует хотя бы одно ограничение, ручное включение не может его обойти.

```ts
import { ChallengeWithUpgradeRestrictions } from './index';

// myChallenge реализует ChallengeRules.
const challenge = new ChallengeWithUpgradeRestrictions(myChallenge, {
  tags: ['cycle'],                  // все улучшения цикла
  upgradeIds: ['fists.damage'],     // и конкретное улучшение
});
challenge.enter(bus); // добавляет отдельный источник challenge:<id>
challenge.leave(bus); // удаляет только этот источник

// Для отображения причины временного отключения:
const status = bus.query('upgrades', { type: 'status', payload: 'fists.damage' });
```

При выходе, в том числе после неудачи, контроллер испытаний вызывает `leave`. Тогда останутся ограничения других источников и личный переключатель игрока. Декоратор снимает своё ограничение также при ошибке входа или выхода. Состояние активных ограничений сериализуется; игровая сборка восстанавливает правила испытаний при запуске.

`MechanicUpgradeDefinition` и `MechanicUpgradeEffect` отдельно описывают эффекты, меняющие поведение или правила. Улучшение сообщает ключ, адресата и параметры; базовая механика сама решает, как применить их через свой `MechanicEffectConsumer`. Примеры: `gameplay/startRules.ts` вычисляет стартовый слой, `weapons/upgradeRules.ts` — предел покупки радиуса. Это позволяет отключить эффект при следующем расчёте без записи в чужой класс. Уже случившиеся действия, например созданная карта, автоматически не откатываются.

## Комбо

Периодическое комбо считает удары отдельно для каждого персонажа и оружия и формирует план с `direct` и `splash`. В `WeaponConfig.combo` задаются доступность, частота, длительность, урон, добавочный радиус и рывок; после открытия комбо переключается командой `weapons` / `set-combo` с `{ characterId, weaponId, enabled }`. Действующий режим использует те же планы атак и модуль движения; отдельные свойства оружия описаны в файлах внутри `weapons/`.

## Что ещё предстоит решить

Новый режим не переносит старое сохранение. Исполнитель `runtime/delivery.ts` добавляет снаряды и упрощённые импульсы луча поверх `CombatModule`; движение прямолинейное, а баланс и часть особых эффектов ещё требуют доработки. Оффлайн-прогресс отсутствует. Общий `StateMapAccess` пока просматривает клетки линейно; перед масштабированием его следует проиндексировать.

Не все параметры `config/defaults.ts` уже влияют на работающий режим: перед изменением проверьте их фактическое использование. Шина не проверяет инварианты при прямом `update` и не сериализует классы модулей: они заново регистрируются при загрузке сохранения.
